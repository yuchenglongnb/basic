### 🧐 一面：核心原理与基础

#### 1. 如何在 GRPO 中提升输出的可解释性？Reward 模型如何训练？

**提升可解释性：**
GRPO（Group Relative Policy Optimization）提升可解释性的核心在于**强制模型生成“推理过程”**。
*   **机制**：在训练数据或 Prompt 设计中，要求模型输出 `<reasoning>...</reasoning>` 和 `<answer>...</answer>` 这样的结构化标签。
*   **奖励设计**：Reward 函数不仅要看最终答案是否正确，还要对推理过程的逻辑性打分。例如，搜索结果中提到的 **PC-GRPO** 引入了“推理-答案一致性（RAC）”监控，利用一个强大的外部模型（如 Qwen-VL-72B）来判断生成的推理轨迹是否在逻辑上支持最终答案，防止模型“瞎编理由凑答案”。

**Reward 模型训练：**
在 GRPO 中，通常不需要像传统 PPO 那样训练一个独立的 Reward Model（RM）来打分，而是直接使用**规则（Rule-based）**或**验证器（Verifier）**。
*   **训练流程**：
    1.  **生成**：对同一个 Prompt，让策略模型生成 $G$ 个不同的输出（Group）。
    2.  **打分**：使用预定义的奖励函数（如格式奖励、正确性奖励）对这 $G$ 个输出打分。
    3.  **计算优势**：计算组内每个输出的优势值（Advantage），即该输出得分减去组内平均得分。
    4.  **优化**：通过最大化优势值来更新策略，同时限制与旧策略的 KL 散度以保持稳定性。

#### 2. 什么是灾难性遗忘？从模型和外置角度说明

**定义**：神经网络在学习新任务（或新数据分布）时，参数发生剧烈更新，导致对旧任务知识的快速丢失。

*   **模型角度（参数层）**：
    *   **原因**：神经网络的权重是共享的。当通过梯度下降优化新任务的 Loss 时，权重的更新方向可能与旧任务的最优方向冲突，覆盖了旧任务学到的特征表示。
    *   **解决**：弹性权重固化（EWC，限制重要权重的变动）、LoRA/Adapter（参数隔离，只训练新增的小参数模块，冻结主干）。
*   **外置角度（数据/系统层）**：
    *   **原因**：训练数据分布的偏移，或者缺乏旧数据的回放。
    *   **解决**：**重放机制（Replay Mechanism）**，即在训练新数据时，混入一部分旧数据（Experience Replay）；或者使用**知识蒸馏**，让新模型在学习新知识的同时，输出分布尽量逼近旧模型。

#### 3. 位置编码是什么？扩展有哪些（ROPE 等）？

**位置编码（PE）**：Transformer 架构本身不具备序列顺序信息（并行计算），必须注入位置信息。

**RoPE (Rotary Positional Embedding)**：
通过复数旋转的方式，将绝对位置信息融入 Query 和 Key 向量中，使得点积运算只与相对位置有关。

**扩展方法（应对长文本）**：
当推理长度超过训练长度时，需要进行位置插值或外推。

| 方法 | 核心原理 | 优缺点 |
| :--- | :--- | :--- |
| **线性插值 (Linear Interpolation)** | 将位置索引线性压缩。例如将 32k 的序列压缩到 4k 的索引空间。 | 实现简单，但会损失高频细节，导致模型困惑度上升。 |
| **动态插值 (NTK-aware)** | 基于神经正切核理论，对低频部分线性插值，高频部分保持不动。 | 兼顾了细节和长度，无需微调或极少微调即可扩展。 |
| **YaRN** | NTK 的优化版，采用多尺度插值策略，针对 RoPE 不同频率设计不同策略。 | 效果最优，支持超长上下文（如 128k），但实现较复杂。 |
| **Spiral RoPE** | 针对 2D 图像/视频数据，将位置编码扩展到多个方向（不仅是轴向），形成螺旋状。 | 解决了传统轴向 RoPE 无法捕捉对角线空间关系的问题。 |

#### 4. 如何提升模型的上下文理解能力？长序列 Attention 方法及推理时延优化

**提升上下文能力**：
*   **架构**：使用上述的 RoPE 扩展技术（YaRN 等）。
*   **数据**：在预训练或 SFT 阶段混入长文本数据（如书籍、长文档）。

**长序列 Attention 类型**：
*   **Sparse Attention (稀疏注意力)**：如 Longformer，限制每个 Token 只关注局部窗口和少量全局 Token，将复杂度从 $O(N^2)$ 降为 $O(N\sqrt{N})$。
*   **Shifted Sparse Attention (LongLoRA)**：通过分组和移位操作，促进组间信息流通，在保持效率的同时捕捉长距离依赖。

**减少推理时延**：
*   **KV Cache 优化**：使用 FlashAttention 加速计算；使用 PagedAttention（如 vLLM）管理显存，减少碎片。
*   **量化**：使用 INT8/FP4 量化模型权重和 KV Cache。
*   **投机采样 (Speculative Decoding)**：用小模型预测，大模型验证，提高生成速度。

#### 5. 现在训练合适的 Reward 一般用多少大小的模型？如何设计专业的 Reward System？

**模型大小**：
*   **趋势**：为了保证评估的准确性和逻辑判断能力，Reward Model 往往比策略模型大得多。例如在视觉推理任务中，会使用 **Qwen-VL-72B** 这样的大模型作为“裁判”来提供反馈。
*   **轻量级**：如果是简单的格式或数学正确性检查，可以使用规则或 7B 以下的小模型。

**专业 Reward System 设计**：
1.  **多维度打分**：
    *   **格式奖励**：是否符合 `<reasoning>` 标签要求。
    *   **正确性奖励**：答案是否与 Ground Truth 匹配（如数学题的精确匹配）。
    *   **语义/流畅度奖励**：通过困惑度（PPL）或语义相似度模型评估。
2.  **课程学习 (Curriculum Learning)**：如 PC-GRPO，根据样本难度动态调整权重，先学简单的，再学难的，避免奖励稀疏导致训练不收敛。
3.  **一致性监控**：检查推理过程和结论是否矛盾。

#### 6. 手撕：最长公共子序列 (LCS)

经典的动态规划问题。

```python
def longestCommonSubsequence(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    # 创建 (m+1) x (n+1) 的 DP 表，初始化为 0
    dp = [ * (n + 1) for _ in range(m + 1)]
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                # 字符相同，左上角值 + 1
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                # 字符不同，取上方或左方的最大值
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
                
    return dp[m][n]
```

### 🚀 二面：工程落地与架构细节

#### 1. Rule-based 和 Model-based 的 Reward 区别及场景

| 维度 | Rule-based (基于规则) | Model-based (基于模型) |
| :--- | :--- | :--- |
| **原理** | 硬编码逻辑（如正则匹配、关键词检查、代码执行结果）。 | 训练一个神经网络（如 RM 或 LLM-as-a-Judge）来打分。 |
| **优点** | 精确、零歧义、计算快、无幻觉。 | 能理解语义、风格、逻辑连贯性等模糊概念。 |
| **缺点** | 无法处理主观评价（如“写得优美”），泛化性差。 | 打分可能有噪声，计算慢（尤其是大模型），存在偏好偏差。 |
| **场景** | 数学计算、代码编译通过、JSON 格式检查。 | 对话流畅度、创意写作、复杂的逻辑推理评估。 |

#### 2. Reward Model 的设计是怎样的，为什么要用 72B 的模型？

**设计**：通常采用 Pairwise Ranking（成对排序）或 Pointwise Scoring（单点打分）。在 GRPO 中，更多是直接作为 Verifier 使用。

**为什么用 72B？**
*   **能力上限**：Reward Model 的能力必须**高于**策略模型。如果策略模型是 7B，用 72B 的模型来评判，能更准确地识别出 7B 模型生成的细微逻辑错误或“投机取巧”行为。
*   **容错率**：大模型作为“老师”，其反馈信号更稠密、更可靠，能引导小模型更快收敛到正确的分布。

#### 3. InternVL 和 Qwen 的 Chat Template 有哪些不同？为什么？

*   **Qwen (纯文本/通用)**：
    *   **Template**：通常使用 `<|im_start|>user\n{content}<|im_end|>\n<|im_start|>assistant`。
    *   **设计**：简洁，适配通用的对话场景，强调角色区分。
*   **InternVL (多模态)**：
    *   **Template**：需要处理图像占位符。例如 `<|im_start|>user\n<image>\n{question}<|im_end|>`。
    *   **差异点**：InternVL 等多模态模型在 Template 中必须包含**图像 Token 的对齐逻辑**。它需要明确告诉模型哪里是图像特征输入的位置，且往往需要处理多轮对话中图像的引用（如“这张图里的...”）。
    *   **原因**：多模态输入不仅是文本序列，还包含视觉 Embedding，Template 必须负责将这些非文本模态正确映射到序列中。

#### 4. 拟人化 Memory 设计技巧，常见 Memory 及实现

**拟人化设计**：模拟人类的海马体（短期）和皮层（长期）机制。

*   **常见类型**：
    1.  **短期记忆 (Short-term)**：即当前的上下文窗口（Context Window）。
    2.  **长期记忆 (Long-term)**：向量数据库（Vector DB），存储历史摘要或关键事实。
    3.  **工作记忆 (Working Memory)**：当前推理过程中的思维链（CoT）或中间变量。

*   **实现方式**：
    *   **滑动窗口**：保留最近 N 轮对话。
    *   **摘要压缩**：定期调用 LLM 将旧对话总结成一段话存入记忆库。
    *   **RAG (检索增强)**：根据当前 Query，从向量库中检索相关历史片段注入上下文。

#### 5. GRPO 均值怎么算的？为什么这样设计？

**计算方式**：
对于同一个 Prompt 生成的 $G$ 个输出（Group），计算这 $G$ 个输出的奖励分数的**算术平均值**。
$$A_i = R_i - \text{mean}(\{R_1, R_2, ..., R_G\})$$
其中 $A_i$ 是第 $i$ 个输出的优势值，$R_i$ 是奖励。

**设计原因**：
*   **基线校准 (Baseline Correction)**：减去均值相当于引入了一个动态基线。如果这一组生成都很差（奖励都低），均值也低，那么相对较好的那个依然能得到正的优势值，从而被鼓励。
*   **方差缩减**：相比于使用全局基线，组内均值能更有效地降低策略梯度的方差，加速收敛。
*   **相对优劣**：GRPO 的核心思想是“矮子里拔将军”，通过组内比较来告诉模型“在这个批次里，哪个是更好的选择”，而不是绝对地追求某个分数。

#### 6. MOE 如何训的？Metragon-Swift 和一般 MS-Swift 区别？EP 如何实现？

**MOE (Mixture of Experts) 训练**：
*   引入路由器（Router/Gating Network），对每个 Token 计算并选择 Top-K 个专家（Experts）进行处理。
*   **难点**：负载均衡（防止某些专家过载，某些闲置），通常通过辅助 Loss 来约束。

**MS-Swift (ModelScope Swift)**：
*   这是阿里开源的轻量级微调框架。
*   **Metragon-Swift**：这可能是面试官提到的特定内部版本或针对 MOE 架构优化的分支（Metragon 意为五角形/五边形，可能指代某种特定的并行策略组合或架构）。通常这类定制版本是为了解决 MOE 训练中的**显存墙**和**通信瓶颈**。

**EP (Expert Parallelism, 专家并行)**：
*   **实现**：将不同的专家网络（Experts）放置在不同的 GPU 上。
*   **流程**：当 Router 决定一个 Token 由 Expert 1 处理时，如果 Expert 1 在 GPU 2 上，则将该 Token 的数据通过 NCCL 通信发送到 GPU 2 进行计算。这需要高效的 All-to-All 通信机制。

#### 7. 长度不一致的数据如何避免 Padding 过长？

在训练 Batch 中，如果序列长度差异大，Padding 会浪费大量计算资源。

*   **解决方案**：
    1.  **Data Collator with Padding to Multiple of 8/64**：不要补齐到 Batch 内最大值，而是补齐到 8 或 64 的倍数（利用 Tensor Core 特性），同时限制最大补齐长度。
    2.  **Bucketing (分桶)**：将长度相近的样本放在同一个 Batch 中。例如，长度 100-200 的样本一批，500-600 的一批。
    3.  **FlashAttention 支持**：FlashAttention 对 Padding 不敏感（它主要关注计算块），但为了显存效率，通常还是建议使用分桶策略。

#### 8. 手撕：股票最佳时机

这是经典的“买卖股票的最佳时机”系列。最基础的是只能买卖一次（LeetCode 121）。

```python
def maxProfit(prices):
    if not prices:
        return 0
    
    min_price = float('inf') # 记录历史最低价
    max_profit = 0           # 记录最大利润
    
    for price in prices:
        # 更新历史最低价
        min_price = min(min_price, price)
        # 计算如果在今天卖出，能获得的利润，并更新最大利润
        max_profit = max(max_profit, price - min_price)
        
    return max_profit
```

**复杂度**：时间 $O(N)$，空间 $O(1)$。
