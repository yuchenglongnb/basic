# 面试演讲稿（MedicalGPT 项目）

## 3-5 分钟版

我做的是一个医疗大模型训练与评测闭环项目，基于 `MedicalGPT` 框架，目标不是单纯把脚本跑通，而是把数据、训练、对齐和评测串成一条可复现的工程链路。整体路线是 `SFT -> Reward Model -> DPO -> 评测`。

第一步我先做了 SFT 的本地 smoke test，目的是验证最小闭环，而不是一开始追求最好指标。我选的是 `Qwen/Qwen2.5-0.5B-Instruct` 作为基座模型，模板用 `qwen`，在仓库自带的 `medical_sft_1K_format.jsonl` 上先跑小样本，实际用了 `train=200`、`eval=20`。这一步在单卡 `RTX 4090 24GB` 上跑通了，显存峰值大约 `85%`。跑完之后我还做了 LoRA merge 和推理 sanity check，确认模型不仅训练目录能产物，而且 merged 模型能正常生成回答。这个阶段的核心价值是把环境、模板、数据格式、输出目录结构都验证稳定。

第二步我做了 Reward Model。RM 这一步本质上是在训练一个偏好打分器：对同一个问题，把 `chosen` 和 `rejected` 两个回答分别拼成完整 prompt，让模型学习 `score(chosen) > score(rejected)`。我用的是仓库里的 `dpo_zh_500.jsonl`，配置是 `LoRA + bf16 + gradient checkpointing`，在单卡 `RTX 4090 48GB` 上跑，训练期间大部分时间显存只占到 `10%` 左右，末尾短暂到 `60%` 左右，说明这套参数比较保守但很稳。最终拿到的 RM 指标是：`eval_loss=1.4586`、`eval_mse=10.4119`、`eval_mae=2.2720`。这一步说明偏好建模链路已经跑通，后面无论接 PPO 还是 DPO 都有基础。

第三步我主线选择了 DPO，而不是 PPO。原因很实际：DPO 对单卡资源更友好，训练更稳定，也更适合在有限时间里做出可复现结果。我是从前面 SFT merge 后的模型继续做 DPO，而不是重新从底模开始，这样链路更完整。配置上我用了 `max_steps=100`、`batch_size=2`、`grad_acc=8`、`bf16`、`gradient_checkpointing`。这一步在 `48GB 4090` 上显存峰值大约 `61.9%`，最终 `eval_loss=0.00299`，说明 DPO 训练本身是稳定完成的。

训练跑通之后，我没有只看 loss，而是做了两类评测。第一类是小样本主观对比评测。我设计了 10 条医疗 prompt，分别让 `SFT` 和 `DPO` 输出回答做对比。这里有一个很典型的正例：在“高尿酸血症患者在饮食管理上最需要注意什么”这个问题上，SFT 出现了明显的重复崩坏，答案后半段失真；而 DPO 输出成了结构化的 1 到 5 点建议，至少在完整性、稳定性和可读性上明显更好。这说明 DPO 确实改善了一部分生成质量问题。

但我没有停留在 DPO 这条线，而是继续往前把‘数据构造是否真的有效’做成了一组独立消融。我先用 CEval 医疗验证集里的 `basic_medicine` 和 `clinical_medicine` 题目做目标分布锚点，再从 `shibing624/medical` 的 `train_zh_0` 里逐步扩候选池，从 `1k -> 5k -> 50k` 观察召回数量和相似度变化。随着候选池扩大，`t70` 召回数从 `4` 提升到 `18`，再到 `207`，`score_max` 也从 `0.732556` 提升到 `0.801393`，说明大池子里确实存在更贴近目标评测分布的样本。

在此基础上，我做了 `Random SFT(500)` 和 `Retrieved_t70 SFT(207)` 两组控制变量实验，并统一用 `lm-evaluation-harness` 跑 `ceval-valid_basic_medicine` 和 `ceval-valid_clinical_medicine`。最终结果是：`basic_medicine` 上两者都是 `0.5789`，持平；`clinical_medicine` 上，召回筛选版本从 `0.4545` 提升到 `0.5000`，提升约 `4.55` 个百分点。这个结果比单纯报一个最好看的分数更重要，因为它说明数据分布对齐不是对所有子任务都等幅提升，但它至少在更贴近临床问答分布的任务上带来了可解释的正向收益。

所以我对这个项目现在的结论有两层。第一层，DPO 改善了部分主观生成质量，但不一定提升知识型 benchmark。第二层，SFT 阶段如果先把训练数据分布和目标评测分布对齐，再去做训练和对齐，能够在部分医学子任务上拿到更可靠的标准化收益。下一步如果继续优化，我会优先从三个方向入手：第一，继续扩大和清洗候选池，尤其是引入 `HealthAI` 结构化病例转 SFT 数据；第二，补更严格的统一验证集和更多阈值/样本量消融；第三，把 CEval、主观样例和偏好评测一起看，而不是只盯单一指标。

这个项目对我最大的价值，不是某一个分数本身，而是我把 `SFT -> RM -> DPO -> 主观评测 -> 标准化 CEval` 这一条链路完整做通了，并且每一步都有日志、输出目录和量化结果可以回溯。我不仅能讲原理，也能讲为什么会出现“主观变好但 CEval 不升”这种实验现象，以及后面准备怎么改。

## 90 秒版

我做的是一个基于 `MedicalGPT` 的医疗大模型训练闭环，完整走了 `SFT -> RM -> DPO -> 评测`。  
SFT 阶段我先用 `Qwen/Qwen2.5-0.5B-Instruct` 在仓库自带医疗数据上做本地 smoke test，完成了训练、LoRA merge 和推理验证，确认最小链路是稳定的。  
RM 阶段我用偏好对数据训练了一个奖励模型，本质上是让模型学会对同一个问题下的 `chosen` 回答打分高于 `rejected`，最终在单卡 `48GB 4090` 上拿到了 `eval_loss=1.4586`、`eval_mse=10.4119`、`eval_mae=2.2720`。  
DPO 阶段我从 SFT merged 模型继续做偏好对齐，显存峰值约 `61.9%`，`eval_loss=0.00299`，说明训练链路本身是稳定跑通的。  
评测上我做了两层。第一层是 DPO 对比，发现 DPO 能改善部分回答的重复崩坏和结构完整性，但在 CEval 医疗子任务上没有带来提升。第二层是数据构造消融，我用 CEval 做锚点、从 `shibing624/medical` 大候选池里做相似度召回筛选，再比较 `Random SFT(500)` 和 `Retrieved_t70 SFT(207)`。结果是 `basic_medicine` 持平，`clinical_medicine` 从 `0.4545` 提升到 `0.5000`。  
所以我的结论不是简单地说某个训练方法更强，而是更真实地说：偏好对齐和数据分布对齐解决的是不同问题，前者改善部分生成质量，后者在部分医学子任务上带来更可靠的 benchmark 收益。这个项目最大的收获是我把训练目标、评测目标和真实实验结果真正对齐起来了。


## 项目最终结论总表

| 模块 | 当前结论 |
|---|---|
| SFT | 最小链路已跑通，形成统一 baseline，后续 CEval baseline 为 `basic=0.5789`、`clinical=0.5000` |
| RM | 偏好打分链路已验证成功，可作为 PPO/GRPO 的 learned reward 来源 |
| DPO | 改善部分主观生成质量，但当前 CEval 未提升：`basic` 下降、`clinical` 持平 |
| 数据分布对齐 | 当前最强正向结果来自这一块：`clinical_medicine 0.4545 -> 0.5000`（`+4.55pp`） |
| PPO | 最小 RLHF 闭环已完整跑通，但统一 CEval 与 SFT 持平，当前更像链路验证成功 |

一句话总结：我现在最有把握讲的不是“某个对齐方法一定更强”，而是“我把 SFT、RM、DPO、PPO 和数据分布对齐分别验证过，并能清楚说明哪些结果是真的正向收益，哪些只是链路打通”。

补充一点，后面我还做了三组 DPO 的统一 CEval 对比：旧 `dpo_zh_500`、医疗 reward 500、医疗 reward 3800。结果是医疗 reward 500 反而下降到 `clinical_medicine=0.4091`，医疗 reward 3800 才恢复到 `0.5000`。这进一步说明，不是“换成医疗偏好数据就一定更好”，而是数据量、数据质量和分布匹配需要同时成立。
我还补了固定 10 条医疗 prompt 的主观对比，现象和 CEval 一致：旧 `dpo_zh_500` 的可读性反而相对最稳，医疗 reward 500 出现了最明显的重复和循环，医疗 reward 3800 比医疗500稳，但仍然有模板化和局部崩坏。后来我又把 `r=8` 和 `r=16` 的统一 CEval 消融补出来，结果显示 `r=16` 并没有带来额外收益，反而在两组医疗 DPO 上都拉低了 `clinical_medicine`，在 `medical3800` 上还把 `basic_medicine` 一起拖低了。所以我现在更明确地认为，当前瓶颈主要还是偏好数据的质量、覆盖和分布，而不是单纯把 LoRA rank 做大。

## 收尾句

如果面试官问“你这个项目最大的收获是什么”，我会回答：

最大的收获是我更清楚地区分了生成质量提升、偏好对齐提升和知识型 benchmark 提升这三个不同维度。以前容易把“回答更顺、更完整”当成模型真的更强，但这次实验让我看到，主观样例提升不一定等于 CEval 提升，所以后续必须用多维评测一起判断模型是否真的更好。

## 高频追问短答

- 为什么选 DPO 不选 PPO：  
  因为我当前资源约束下，DPO 更稳定、更省卡，能更快形成可复现结果；PPO 我后来补了一条最小闭环，而且已经完整跑通并产出模型，也做了统一 CEval，但结果和 SFT 持平，没有形成明确 benchmark 增益，所以当前更像 RLHF 链路验证，而不是更优主线。

- 为什么 DPO 没提升 CEval：  
  因为 DPO 优化的是偏好分布，不一定等价于知识选择题准确率；如果偏好数据和 benchmark 目标不一致，就可能出现主观提升但 CEval 不升。

- 你怎么证明自己不是只会跑脚本：  
  我保留了每一步的 `console`、`run_meta`、训练产物和评测结果，并且能解释每次报错、参数取舍和结果回退的原因。



## DPO LoRA Rank 消融：为什么 `r=16` 反而更差

这轮消融我把同一套医疗偏好数据分别用 `LoRA r=8` 和 `r=16` 跑了一遍，并同时看了统一 CEval 和固定 10 条医疗 prompt 的主观输出，结论很一致：**当前这条 DPO 线里，`r=8` 明显比 `r=16` 更稳。**

统一 CEval 结果：

| 组别 | basic_medicine | clinical_medicine |
|---|---:|---:|
| `medical500, r=8` | `0.4737` | `0.4091` |
| `medical500, r=16` | `0.5263` | `0.3636` |
| `medical3800, r=8` | `0.5789` | `0.5000` |
| `medical3800, r=16` | `0.4737` | `0.4091` |

固定 10 条医疗 prompt 主观对比：
- `medical500, r=8`：虽然已经有重复和冗长，但多数回答还保留了基本结构。
- `medical500, r=16`：开始出现更明显的长句堆砌、概念外延过度和局部循环，主观质量更差。
- `medical3800, r=8`：仍有模板化，但整体还能维持在“可读、可交付”的边缘。
- `medical3800, r=16`：退化最明显，多个问题上出现高频短语机械重复，例如“通过血液”“需要及时去医院”“刺激性的食物”等，已经接近明显生成崩坏。

因此当前最稳的解释不是“`r=8` 容量不够”，而是：
- 当前瓶颈主要在偏好数据的质量、覆盖和分布，而不是 rank 太小。
- 更高 rank 在这组医疗偏好数据上更像是在放大噪声、模板偏好和局部错误模式。
- 对 `0.5B` 这条 DPO 线来说，至少在当前数据和超参下，`r=8` 已经够用，`r=16` 没有带来额外收益，反而破坏了 benchmark 和主观生成质量。

一句话总结：**LoRA rank 变大并没有救回 DPO，反而进一步证明当前主导效果的核心变量是偏好数据本身，而不是单纯增加参数化容量。**



## 项目最终可讲结论树

### 1. 最顶层结论
- 这套医疗 LLM 项目里，**当前最可靠、最可解释的正向收益来自数据分布对齐**，不是单纯增加偏好训练或堆更复杂的 RLHF。
- `SFT -> RM -> DPO -> PPO` 这条链我已经完整跑通，因此工程闭环是成立的；但从最终 benchmark 来看，**工程链路跑通不等于效果自然变强**。

### 2. 最强正向结果来自哪里
- 最强结果来自 `Random SFT(500)` vs `Retrieved_t70 SFT(207)` 这组对比。
- 在统一 CEval 上：
  - `basic_medicine`：`0.5789 -> 0.5789`
  - `clinical_medicine`：`0.4545 -> 0.5000`
- 这说明：**数据分布更贴目标任务，比单纯扩大样本或盲目做偏好对齐更有效。**

### 3. DPO 这条线最后说明了什么
- 三组 DPO 对比：
  - `old500`：`0.4737 / 0.5000`
  - `medical500`：`0.4737 / 0.4091`
  - `medical3800`：`0.5789 / 0.5000`
- 主观样例对比也一致：
  - `old500` 可读性反而相对最稳。
  - `medical500` 重复、循环、啰嗦最明显。
  - `medical3800` 比 `medical500` 稳，但更多是在“把退化拉回 baseline”，而不是明显超过 baseline。
- 结论：**把偏好数据换成医疗数据，不会自动带来更好结果；500 条不稳，3800 条能恢复，但当前仍没有超过最强 SFT 基线。**

### 4. LoRA rank 消融最后说明了什么
- `r=8` vs `r=16` 的统一 CEval 和固定 10 条 prompt 对比都表明：`r=16` 更差。
- 特别是 `medical3800`：
  - `r=8`：`0.5789 / 0.5000`
  - `r=16`：`0.4737 / 0.4091`
- 主观上 `r=16` 还出现更严重的短语循环和生成崩坏。
- 结论：**当前瓶颈不在 LoRA 容量太小，而在偏好数据的质量、覆盖和分布。**

### 5. PPO 这条线最后说明了什么
- PPO 最小闭环已经完整跑完：RM merge 成功，PPO 训练完成，模型保存成功，后续 CEval 也跑通了。
- 统一 CEval 结果：
  - `SFT`：`0.5789 / 0.5000`
  - `PPO`：`0.5789 / 0.5000`
- 同时 PPO 训练和样例里暴露出：高 KL、right-padding 告警、边界污染、中英混杂。
- 结论：**PPO 当前最准确的定义是 RLHF 工程闭环验证成功，但没有形成额外 benchmark 收益。**

### 6. 这个项目最终想说明的核心判断
- 决定效果的核心变量，不是“模型更大”“LoRA rank 更高”或“方法更复杂”本身。
- 真正更关键的是：
  - 数据是否高质量
  - 数据是否和目标评测分布对齐
  - 偏好数据是否覆盖稳定
  - 训练目标是否真的对应你想优化的 benchmark
- 所以这版项目最后最有说服力的技术判断是：
  - **数据分布对齐 > 盲目扩数据**
  - **高质量偏好数据 > 只换成医疗标签的数据**
  - **稳定可解释的 baseline > 复杂但没有收益的后处理链路**

### 7. 面试时一句话收束
> 我把 `SFT -> RM -> DPO -> PPO` 这条医疗 LLM 对齐链完整跑通了，但最终发现最稳定、最可解释的收益来自数据分布对齐，而不是更复杂的偏好优化或更高的 LoRA 容量。这让我对“什么变量真正决定效果”有了更清晰的判断：不是方法名字更高级，而是数据质量、覆盖和目标分布是否匹配。
