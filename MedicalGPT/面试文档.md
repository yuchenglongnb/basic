# 医疗大模型训练与评测闭环 — 面试完整项目文档

---

## 一、项目背景与目标

**背景**：以 HealthAI-2025 天池竞赛临床病例数据为基础，结合 `shibing624/medical` 开源医疗数据集（200w条），基于 MedicalGPT 框架对 Qwen2.5-0.5B 进行医疗领域全链路微调。

**核心问题**：随机采样 SFT 数据导致 CEval 医疗指标不升反降（Domain Mismatch）。

**目标**：
- 建立数据构造 → 训练 → 评测三环咬合的可复现改进闭环
- 覆盖 SFT → Reward Modeling → DPO 完整对齐流程
- 用 CEval 医疗指标量化每一步的真实提升

**核心价值**：不是"跑通框架"，而是能用消融实验解释每一步为什么有效。

---

## 二、技术架构

```
数据层
├── HealthAI-2025 临床病例数据（结构化EHR）
├── shibing624/medical（200w条，按任务类型拆分）
│   ├── finetune/train_zh_0.json → SFT候选池
│   ├── reward/train.json        → RM/DPO偏好对
│   └── pretrain/*.json          → PT语料
└── CEval医疗验证集              → 分布锚点

训练层（MedicalGPT框架）
├── Stage 1: PT（增量预训练）
├── Stage 2: SFT（监督微调，LoRA r=8）
├── Stage 3: Reward Modeling（Pairwise Ranking Loss）
└── Stage 4: DPO（直接偏好优化）

评测层（lm-evaluation-harness）
├── CEval medical（basic_medicine + clinical_medicine）
├── PPL（困惑度）
└── 主观对比评测（DPO vs SFT）
```

**硬件**：单卡 RTX 4090 (48G)，bf16 + gradient checkpointing，显存峰值控制在 85% 以内。

## 三、核心模块

### 3.1 数据构造：向量召回分布对齐

**问题**：随机采样 SFT 数据，CEval 医疗指标不升反降。

**根因**：训练分布与目标评测分布不对齐（Domain Mismatch）。

**解决方案**：以 CEval 验证集为目标分布锚点，用 `bge-large-zh` 做向量召回筛选。

```
CEval 医疗验证集（题干+选项，不含答案）
      ↓ bge-large-zh 向量化
目标分布向量库
      ↓ cosine similarity 过滤（阈值0.70）
shibing624/medical 候选池（50k）
      ↓
高质量SFT训练集（与评测分布对齐）
```

**消融实验结果**：

| 组别 | clinical_medicine | basic_medicine |
|---|---|---|
| Random SFT(500) | 45.45% | 57.89% |
| Retrieved_t70 SFT(207) | **50.00%（+4.55pp）** | 57.89%（持平） |

**为什么只在 clinical_medicine 提升**：召回样本更接近临床问答和病例处理风格，而 basic_medicine 偏基础知识点，当前召回样本未必比随机采样更占优。这是合理的分布对齐效果，不是全面提升。

### 3.2 Reward Modeling

- 数据：`shibing624/medical/reward/train.json`，4000条偏好对（chosen=医生答复，rejected=本草模型答复）
- 损失函数：Pairwise Ranking Loss

$$\mathcal{L}_{RM} = -\log \sigma(r_\theta(x, y_w) - r_\theta(x, y_l))$$

- 训练结果：eval_loss=1.46，eval_mae=2.27

### 3.3 DPO 偏好对齐

- 以 SFT merged 模型为起点
- 损失函数：直接在偏好对上优化，无需显式 RM 和 RL 训练
- 训练结果：eval_loss=0.003
- 主观评测：显著改善了医疗问答中的**重复崩坏**和**结构完整性**问题

## 四、关键技术细节

### LoRA 配置

```python
lora_rank = 8
lora_alpha = 32        # 通常是 rank 的 2-4 倍
lora_dropout = 0.05
target_modules = ["q_proj", "v_proj"]
```

**原理**：将权重更新分解为两个低秩矩阵 $\Delta W = AB$，只训练 A、B，参数量减少 >90%。

### DPO vs PPO 选择

| 维度 | PPO | DPO |
|---|---|---|
| 流程复杂度 | 高（4模型同时维护） | 低（SFT模型+偏好数据） |
| 训练稳定性 | 低（超参敏感） | 高 |
| 显存占用 | 极高 | 较低 |
| 本项目选择 | — | ✓ 资源受限，快速迭代 |

### CEval 评测命令

```bash
lm_eval --model hf \
    --model_args pretrained=outputs/sft_merged \
    --tasks ceval-valid_clinical_medicine,ceval-valid_basic_medicine \
    --device cuda:0 \
    --batch_size 8
```

### 数据任务边界划分

- `finetune/train_zh_0.json` → SFT候选池（中文问答，与CEval分布最匹配）
- `reward/train.json` → RM/DPO（偏好排序，不混入SFT）
- `pretrain/*.json` → PT（长文本，不适合指令跟随任务）

## 五、难点与优化

### 难点1：数据分布不对齐

**现象**：随机采样医疗数据做SFT，CEval指标不升反降。

**优化**：以CEval验证集为锚点，用embedding相似度过滤，确保训练分布与评测分布对齐。

**关键决策**：阈值不能拍脑袋定，要做消融扫描（0.70/0.75/0.80三档），画"数据量-质量-指标"帕累托关系。

### 难点2：候选池规模与召回数量的矛盾

**现象**：1k候选池时，t70只召回4条，t75召回0条，无法形成有效SFT对比。

**优化**：逐步扩池（1k→5k→50k），随着候选池扩大，召回数量和score_max稳定上升：

| 候选池规模 | t70召回数 | t75召回数 | score_max |
|---|---|---|---|
| 1k | 4 | 0 | 0.7326 |
| 5k | 18 | 2 | 0.7601 |
| 50k | 207 | 19 | 0.8014 |

### 难点3：DPO 重复崩坏问题

**现象**：SFT模型在医疗问答中出现重复输出和结构不完整。

**优化**：DPO偏好对齐后，主观对比评测显示重复崩坏和结构完整性显著改善（eval_loss=0.003）。

### 难点4：显存控制

**方案**：LoRA(r=8) + bf16 + gradient checkpointing，单卡 RTX 4090 完成全链路训练，显存峰值控制在 85% 以内。

## 六、八股原理与常见追问

### Q1：用CEval验证集做召回锚点，是数据泄露吗？

不是。用的是 **验证集（dev set）** 而非测试集，且锚点文本只包含题干+选项，不含标准答案。本质是 **领域自适应（Domain Adaptation）**，让训练分布与目标任务分布对齐，是工业界通行做法。测试集全程 unseen，不存在泄露。

### Q2：LoRA 的原理？rank 怎么选？

预训练模型权重的更新量 $\Delta W$ 本质上是低秩的，将其分解为 $\Delta W = AB$（$r \ll \min(d,k)$），只训练 A、B，冻结原始权重。rank 选择看任务复杂度：简单问答 r=4~8，复杂推理 r=16~64。本项目用 r=8，在效果和参数量之间取平衡。

### Q3：DPO 的损失函数是什么？

$$\mathcal{L}_{DPO} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)\right]$$

直接在偏好对上优化，无需显式 RM 和 RL 训练，去掉了 PPO 的 4 模型架构。

### Q4：PPO 中 KL 惩罚项的作用？

防止模型"奖励黑客"（Reward Hacking）。Reward Model 不完美，没有 KL 约束时 Actor 会找到让 RM 打高分但实际质量差的捷径（如重复词、格式化但无意义的文本）。KL 约束确保 Actor 不偏离 SFT 初始版本太远。

### Q5：CEval 的局限性？

① 纯选择题，无法评估开放式对话和长文生成能力；② 每科目约200题，样本方差较大；③ 静态数据集，存在数据污染风险。生产中应结合人工评测（医生评分）和 GPT-4 Judge 综合判断。

### Q6：PPL 下降一定代表模型变好了吗？

不一定。SFT 后医疗语料 PPL 下降，但通用任务 PPL 可能上升（灾难性遗忘）。需要同时检测多个维度，不能只看单一指标。

### Q7：为什么选 bge-large-zh 做 embedding？

中文检索能力强，在中文语义检索 MTEB 榜单表现最优，对医疗术语的语义理解优于通用 OpenAI Embedding。向量维度 1024，支持批量推理。面试时的关键点：不是凭主观规则筛数据，而是用统一语义空间做分布对齐。

### Q8：如何证明数据构造路线有效？

三层证据：
1. **召回统计**：随着候选池扩大，召回数量和 score_max 稳定上升
2. **训练闭环**：Random SFT 和 Retrieved_t70 SFT 都成功训练并产出可加载模型
3. **统一 CEval 评测**：同一套评测下，召回筛选版本在 clinical_medicine 上提升 4.55pp

---

**一句话总结**：数据分布对齐（向量召回）→ SFT → RM → DPO，三环咬合，CEval clinical_medicine 从 45.45% 提升至 50.00%，DPO 解决重复崩坏，全链路单卡 RTX 4090 可复现。
